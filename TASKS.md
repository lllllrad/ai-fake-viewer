# Implementation work items

Current behavior is owned by the [documentation index](docs/README.md). Historical experiments in [verification](VERIFICATION_REPORT.md) do not establish current live approval.

| Area                   | Implemented                                                                                                                                                       | Remaining acceptance                                                                                                     |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Viewer participation   | Exact staged commands, delivered-notice confirmation, 14+ self-declaration (not verification), scoped epochs, old-event rejection, manual actual-event assistance | Real SDK ordering, platform approvals, published notices and age-response procedure                                      |
| Processing profile     | Default fail-closed operator/provider/publication/permission profile; explicit API/subscription contract and model, no automatic provider fallback                | Selected service account region/retention/data-sharing eligibility and legal basis                                       |
| Inputs                 | Approved official receivers and automatic fixed notices; unconsented text excluded; audio/video and unofficial SOOP disabled live                                 | SOOP SDK/YouTube OAuth fixed-notice senders implemented; real account send/echo and allowed-rate acceptance remain       |
| Context and withdrawal | Synchronous invalidation, raw/derived removal, request cancellation, filtered reconnects, preapproved fixed anonymous categories                                  | Provider handling of already delivered requests; actual anonymity assessment                                             |
| Session storage        | App memory-only chat/consent/personas/summary/budget; no restart recovery, no live transcript export                                                              | Old files/exports cleanup; host swap/dump/backup review                                                                  |
| Rights and video       | Separate minimal durable request queue, optional content inventory, app/provider/video/copy confirmations and resolved-record deletion                            | Actual editing, provider/platform procedures and result notification                                                     |
| Persona P0             | Six automatic research-informed synthetic viewers, presence/pacing/evidence/review and local publication                                                          | [Known limitations](docs/ai-viewer-persona-system-spec.md#남은-구현과-검증), real model naturalness                      |
| Dashboard              | Primary input/AI controls, explicit disclosure wording, staged participation/profile/rights UI                                                                    | [Remaining UI acceptance](docs/admin-dashboard-functional-spec.md#현재-구현과-요구사항의-차이), full accessibility audit |
| Documentation          | Current profile runbook, requirements/test mapping, environment wrapper and local-link checker                                                                    | Update with every behavior change; external link/contract verification is separate                                       |

Standalone legacy persistent Store, capture/STT/Jev and manual persona authoring tests remain for library regression coverage. They are not exposed as alternate live privacy paths. No real API, platform sender or VOD operation was performed as part of this implementation. See [privacy acceptance table](docs/privacy-implementation.md#인수-테스트와-운영에서-확인할-항목) for T01–T26 scope.
